# 网页账号、密码与连接管理

核对日期：2026-11-18。适用于启用 `config.oauth.example.json` 中 OAuth 配置的 HTTPS 实例。当前为开发联调版，新增功能不代表全部产品或生产安全验收完成。

## 1. 用户入口

| 地址 | 用户操作 |
| --- | --- |
| `/account` | 查看当前登录账号，进入连接管理、改密或退出网页 |
| `/account/login` | 使用平台自带账号登录账号管理 |
| `/account/password` | 输入当前密码、新密码及确认密码，更新后重新登录 |
| `/account/connections` | 分页查看本人尚未过期的平台会话和助手授权 |
| `/account/connections/revoke?clientId=...` | 查看撤销影响，再通过页面按钮确认撤销 |

所有写操作使用 POST，GET 不修改密码或撤销会话。退出本网页的操作在账号首页和改密页，作用于该次网页会话，临时密码用户也可在更新前退出。客户端 OAuth 登录状态与账号管理网页会话分别管理；需要让助手断开时，应撤销对应连接。

连接列表按客户端标识聚合。一个标识可能对应多台电脑或多个助手；确认页明确说明它们会一起撤销。管理员需要为不同助手分别分配可区分的 ID，才能按助手分别撤销；客户端 ID 是会话标签，不证明软件真伪。

页面只展示当前账号的数据。点击撤销后，服务端按当前会话解析所属用户，撤销其指定客户端的平台会话，以及关联的 OAuth 授权码、访问令牌、刷新令牌和授权记录。其他用户使用同一客户端标识的连接保持有效。用户撤销包含当前网页会话的标识时，会返回登录页。

## 2. 临时密码更新

管理员重置密码仍通过现有管理接口完成，临时密码由企业按可信流程交付。员工有两种网页操作方式：

1. 从助手发起连接：在企业 OAuth 登录页面输入临时密码后，页面显示“更新临时密码”。输入当前临时密码和两次新密码，更新成功后继续原来的授权流程，再由本人确认客户端权限。不需要手工调用 API，也不要求重新配置助手。
2. 直接访问 `/account`：使用临时密码登录后，自动进入密码更新页；连接列表等页面在更新前不能访问。更新成功退出旧会话，使用新密码重新登录。

新密码沿用已有 12～1024 字符长度约束，不能与当前密码相同；两次输入必须一致。页面允许密码管理器和粘贴，不回显密码值，也不把密码写入日志或业务审计。管理员创建账号的初始密码目前仍不会自动标记为临时密码，正式邀请流程尚待开发。

更新密码会撤销该用户全部已有平台会话和 OAuth 授权。OAuth 临时密码流程在当前交互中重新确认了当前密码，因此可继续本次登录；新的权限确认仍由 oidc-provider 执行，不会因为改密自动扩展业务权限。

## 3. 会话和表单保护

- 账号管理网页会话最长 30 分钟；OAuth 临时改密会话最长 10 分钟。这两个期限写入服务端平台会话，签名 Cookie 也包含有效期，不能仅靠浏览器 Cookie 的过期删除实现限制。普通 API 登录的默认会话期限仍为 8 小时。
- 网页使用独立 `__Host-` 前缀的 Secure、HttpOnly、SameSite=Lax Cookie，Path 为 `/`，无 Domain；Cookie 内的会话凭证仅通过 HTTPS 传输，不写入 HTML、URL 或浏览器脚本。SQLite 中继续只保存平台会话凭证的摘要。
- Cookie 由现有独立 OAuth Cookie 密钥签名；服务端复查签名、有效期及实际会话。临时改密 Cookie 额外绑定 OAuth 交互 UID，不能用于切换另一个账号或交互。
- 登录、退出、改密和撤销各自校验 CSRF，并要求 POST Origin 与企业源一致。撤销 CSRF 还绑定目标客户端；临时改密从普通登录切换时产生新的会话绑定 CSRF。重复 Cookie、重复字段、未知字段和无效 UTF-8 拒绝处理，表单上限 16 KiB。
- 页面禁止嵌入、限制 CSP、不缓存、无外部脚本/字体。用户名和客户端名称转义输出，输入框有可见标签和密码管理器属性，按钮及焦点沿用既有界面规则。
- 浏览器登录与改密共用来源和规范化账号限流：每来源每分钟 10 次、每账号每 15 分钟 5 次验证尝试；成功尝试也计数。登录和改密校验失败还共享数据库中的连续失败计数，累计 5 次锁定密码验证 15 分钟，防止绕过网页直接调用改密 API 继续猜测。

服务器重启会清空内存限流窗口，但不会清空数据库中的失败锁定。账号停用、管理员再次重置密码、会话到期及撤销后，原有网页操作也会失效。网页会话不支持无条件延期或“永久登录”。

## 4. API 与数据范围

新增 `GET /v1/connections`，使用平台 Authorization Bearer 会话，不能使用 MCP 的 `mcp:read` OAuth 令牌或网页 Cookie 代替。可选查询参数 `after` 为上一页返回的客户端标识；拒绝未知参数、重复游标和非法游标。

响应示例：

```json
{
  "connections": [
    {
      "clientId": "enterprise-desktop",
      "platformSessions": 0,
      "oauthGrants": 1,
      "expiresAt": 1795000000000
    }
  ],
  "nextCursor": null
}
```

每页最多 50 个客户端，按客户端标识稳定排序。`expiresAt` 是该客户端摘要中记录的最晚到期值，不能当作每一条会话的有效期承诺；访问权限仍逐请求校验。列表不返回原始会话、授权码、令牌、授权 ID、其他用户身份或内部数据目标地址。

撤销继续使用已有 `/v1/revoke-client` 服务逻辑；网页没有新增可由客户端传入 userId 的撤销权限。临时密码会话不能读取连接列表；MCP OAuth 身份也不能调用这个账号维护服务。无需升级数据库版本，继续使用现有版本 2。

## 5. 验证与限制

新增验证覆盖真实本机 HTTPS 表单、网页登录/改密、临时密码续接原 OAuth PKCE 与用户确认、历史授权撤销、跨用户隔离、Cookie 签名/服务端过期、动作/目标/会话绑定 CSRF、字段和游标校验、分页、密码验证锁定及账号重置后的失效。全部使用虚构账号和公开测试证书，没有修改用户实际助手配置或访问真实企业服务。

本轮完整回归结果记录在 `03-implementation-status.md`。UI 已生成隔离的静态预览材料，但浏览器自动化两次返回 Windows `GetCursorPos` 访问拒绝，未能完成真实浏览器视觉、移动布局或辅助技术验收。不能将 HTTPS 表单模拟称为浏览器实机通过。

可选 `test-support/account-preview.mjs` 会用虚构账号从本机 HTTPS 测试实例捕获页面，关闭该实例，再以回环 HTTP 提供静态快照；不接受 POST 或真实账号密码。仅用于开发视觉检查，不是平台启动命令，不应外网部署。预览服务已在本轮结束前停止。
