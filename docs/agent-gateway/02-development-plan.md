# 开源企业 AI 连接网关：功能开发详细规划

版本：V0.1｜日期：2026-11-17｜对应产品需求 V0.1｜状态：开发规划及首项规则实现

## 1. 总体架构与信任边界

```text
WorkBuddy / Codex / DeepSeek Harness 适配包
  └── MCP over HTTPS；必要时本地受限桥接
         ↓ 身份认证与 API/MCP 接入
      统一授权与业务服务 ─── 连接器/目标地址策略 ──→ 企业 Agent / 工作流 API
         ↓              ↓
      私有隔离存储 → 独立审查工作进程 → 受控文件存储
         ↓              ↓                    ↓
      PostgreSQL   扫描服务/沙箱          审计、备份
```

初期建议模块化服务加独立沙箱工作进程。所有请求由验证过的认证中间件构建主体，插件提供的身份和角色均不可信。下游连接器拥有独立身份和凭据。网络入口使用 HTTPS；可信反向代理与内部通信的信任关系必须明确定义。扫描区无任意外网和生产密钥。

技术栈、MCP SDK、身份组件及版本为实施选型，不在未验证时锁定；选成熟维护方案，记录兼容性、许可与供应链风险。绝不自行设计密码算法、OAuth 协议或恶意扫描引擎。

## 2. 交付里程碑与依赖

| 阶段 | 内容 | 完成门槛 |
| --- | --- | --- |
| M0 | 需求基线、威胁模型、协议和客户端版本实测、规则内核 | 文档评审；纯规则测试通过；列出尚无实现的安全功能 |
| M1 | 单企业部署、自带账号、权限、目标登记、审计和 API | 账号停用、越权、撤权、目标网络控制集成测试通过 |
| M2 | 隔离上传、格式探测、受限解析、扫描器适配和扫描状态 | 真正扫描服务接入；扫描失败关闭；无隔离区旁路 |
| M3 | 文件版本绑定、交付前重鉴权、下游签收、幂等与恢复 | 模拟崩溃、撤权、目标停用、重试与回执测试通过 |
| M4 | 三客户端插件/Skill 与登录、兼容性矩阵 | 指定版本端到端安装、登录、撤权、上传通过；不兼容项公开 |
| M5 | 托管部署材料、升级、备份、恢复、安全测试及试点 | 安全审查、恢复演练、真实用户安装测试完成后才可生产试点 |

里程碑可调整，不能以示例规则、模拟扫描或文档代替安全能力。具体工期需在人员、环境和客户端版本确定后估算。

## 3. 核心模块拆分

1. 身份：账户、密码登录、登录节流、会话/令牌、吊销、重置和管理员初始化；选成熟认证组件。MCP OAuth 支持以 SDK 和客户端兼容验证为准。
2. 授权：基于服务端主体、角色、组、动作、资源、数据级别和目标的默认拒绝决策；对列表、下载、状态、工具和后台交付统一执行。
3. 接入：MCP 工具适配至同一业务服务；普通 API 不绕过相同规则。标准错误码，工具参数经过 schema 校验。
4. 目标登记：企业管理员审批目标、URL、认证材料、允许数据/操作。拦截任意地址、重定向及 DNS 重绑定；按企业批准的网络目标实施连接时校验，不能简单地信任用户输入的 URL。
5. 上传：创建提交、分配短期限定上传、服务器生成对象键、隔离存储、计算真实摘要，记录不可变版本；不信任客户端类型声明和摘要。
6. 审查：实际文件类型识别、扫描、格式解析及数据规则，全部审查阶段由受限工作进程执行；扫描引擎、规则/病毒库版本及完整性记录，故障不放行。
7. 交付：绑定文件摘要、扫描策略版本和目标；执行前重新查权限、用户状态和目标；使用事务性 outbox/任务表，带租约、超时和幂等。
8. 审计：追加事件、最小化字段；审查与交付事件可追溯但不记录令牌或全文；审计访问独立授权。
9. 插件：各客户端独立打包或配置适配，配套通用技能；不覆盖用户已有配置。构建签名、完整性校验、版本锁定与升级/卸载设计。

## 4. 最小数据模型

| 对象 | 字段与约束 |
| --- | --- |
| user、group、membership | 稳定 ID、状态、成员关系；认证凭证与业务用户分离 |
| client_authorization | 用户、客户端、范围、状态、撤销/过期时间 |
| service_account、connector | 独立服务身份、目标地址、目标状态、凭据引用、类型范围 |
| policy、policy_version | 主体组、动作、资源/目标、格式/级别、版本与启用状态 |
| submission、file_version | 提交人、目标、对象键、服务端内容摘要、类型、版本、状态 |
| scan_result | 绑定 file_version、摘要、策略版本、引擎/规则版本、结果与完成时间 |
| delivery、delivery_attempt | 提交、文件版本、目标、幂等键、状态、接收方回执、尝试记录 |
| audit_event、outbox | 操作主体、资源、结果、时间、追踪号；事件和业务状态事务一致 |

对象访问和更新使用事务、乐观并发或锁定；授权不能仅依赖客户端携带的对象 ID。对象存储不可公开，隔离桶和交付桶的访问角色不同。存储和备份生命周期、删除与密钥管理待企业决策。

## 5. 对外能力与契约

| 能力 | 输入概要 | 服务端要求 |
| --- | --- | --- |
| 查看当前身份/连接 | 无敏感参数 | 返回服务端认证主体及最小可见范围 |
| 创建提交 | 已登记目标、类型、幂等键 | 检查权限、目标和请求限制 |
| 上传文件 | 服务端限定对象及短期上传授权 | 流式限制大小，计算摘要，写隔离区 |
| 查询提交 | 提交 ID | 每次检查读取权限，隐藏不属于用户的资源 |
| 提交表单 | 目标、schema 版本、数据、幂等键 | 禁止未知字段，校验权限和范围 |
| 交付给企业系统 | 固定提交版本 | 重新鉴权、审查与目标检查；回执与重试 |

下游契约应包括提交/文件版本、任务编号、幂等键、授权范围、接收回执和错误分类。下游须实现去重才能保障重试不重复产生业务效果；无此能力时暴露“不确定”，不得自动称为恰好一次。下载授权应短期、单对象、限定用途，尽量避免 URL 凭证泄漏到日志。

## 6. 安全边界与失败策略

- 格式识别不等于恶意扫描，文件扩展名、MIME 和客户端摘要均不可信。
- 扫描器不可用、过期策略、失败、超时、未知结果或文件变更均禁止交付；在目标政策变化时重新判断。
- 解析禁用外部网络及本地敏感文件访问，XML 禁外部实体，Office 不运行宏或外链。
- 交付处理器验证实时用户状态、原始授权与目标权限；后台服务账号不扩大原发起人的授权。
- 凭据不进入技能文本、MCP 工具输出、URL、日志或模型上下文；密钥使用受控存储。
- 隔离区只有审查服务可以读取；受控交付授权绑定具体文件版本和目标。
- 审查结果仅表示符合当前检查规则，不能承诺绝对安全；提供报告和版本追踪。

## 7. 客户端适配与兼容矩阵

Codex：使用其受支持的插件封装技能和远程 MCP；WorkBuddy：以其正式支持的插件/连接器或 MCP 入口为准；DeepSeek Harness：利用官方 MCP 客户端和插件机制。各客户端需分别验证：受支持版本、安装方式、远程传输、交互式登录、令牌刷新、退出/撤权、无权限提示及卸载；缺失能力通过经过安全审查的本地桥接解决，禁止明文长期 Token。不得把三个客户端包装格式视为相同。

## 9. 测试与发布门禁

单元测试覆盖授权矩阵和状态机；集成测试覆盖真实数据库、对象存储、扫描器、真实认证和下游假服务；安全测试覆盖权限绕过、SSRF/DNS 重绑定、XML 外联、解压炸弹、上传竞态、令牌泄漏、提示词注入和频率限制；端到端验证三客户端；故障测试覆盖断电、扫描超时、重复投递、目标失效及备份恢复。危险样本在隔离测试环境使用，文档输出不包含密钥。

上线前必须完成真实认证、真实扫描器和隔离验证、TLS 和目标地址控制、可恢复备份、独立安全审查与三客户端实测；纯内存规则实现不可对外提供生产服务。
